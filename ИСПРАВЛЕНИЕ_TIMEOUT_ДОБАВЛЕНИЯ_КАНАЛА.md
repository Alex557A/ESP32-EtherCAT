# Исправление проблемы timeout при добавлении канала

## Проблема

При нажатии кнопки "Apply" для добавления канала возникает ошибка: **"Ошибка: timeout"**

## Причина

Timeout для операции `set_gpio_channel` был слишком коротким (2 секунды), что могло быть недостаточно при:
- Медленной обработке на ESP32
- Задержках в сети
- Больших объемах данных

## Исправления

### 1. Увеличен timeout для операций с каналами

**В `bridge.js`:**

- `set_gpio_channel`: **2000ms → 5000ms** (5 секунд)
- `get_gpio_channels`: **1200ms → 3000ms** (3 секунды)
- `delete_gpio_channel`: **2000ms → 3000ms** (3 секунды)

### 2. Добавлено подробное логирование

**В `sendJsonRpcOnce()`:**
- Логирование отправки команды
- Логирование получения ответа
- Логирование ошибок и таймаутов
- Логирование не-JSON строк для отладки

**В API endpoints:**
- Логирование параметров запроса
- Логирование ответа
- Логирование ошибок

### 3. Улучшена обработка таймаутов

- Добавлен socket timeout (timeoutMs + 500ms)
- Улучшена обработка закрытия соединения
- Логирование буфера при закрытии соединения

## Как проверить

### 1. Перезапустите bridge.js

```bash
# Остановите текущий процесс (Ctrl+C)
node bridge.js
```

### 2. Попробуйте добавить канал

1. Откройте веб-интерфейс
2. Выберите категорию "USB Keyboard"
3. Нажмите клавишу на физической клавиатуре
4. Заполните поле Name
5. Нажмите "Apply"

### 3. Проверьте логи bridge.js

В консоли bridge.js должны появиться логи:
```
[sendJsonRpcOnce] Sending to 192.168.20.1:23 - set_gpio_channel (id=...)
[sendJsonRpcOnce] Received response for set_gpio_channel (id=...): {...}
[API] set_gpio_channel response: {...}
```

Если видите timeout:
```
[sendJsonRpcOnce] Timeout after 5000ms for set_gpio_channel to 192.168.20.1
[API] set_gpio_channel error: timeout after 5000ms
```

## Диагностика

### Если timeout все еще возникает:

1. **Проверьте Serial Monitor ESP32:**
   - Должны быть видны команды `set_gpio_channel`
   - Должны быть видны ответы от ESP32

2. **Проверьте логи bridge.js:**
   - Видно ли отправку команды?
   - Видно ли получение ответа?
   - Какой timeout установлен?

3. **Проверьте сеть:**
   ```powershell
   Test-NetConnection -ComputerName 192.168.20.1 -Port 23
   ```

4. **Проверьте размер данных:**
   - Если канал содержит много данных, возможно буфер переполняется
   - Проверьте логи на наличие "response_too_large"

## Дополнительные улучшения

Если проблема сохраняется, можно:

1. **Увеличить timeout еще больше:**
   ```javascript
   const resp = await sendJsonRpcOnce(host, 'set_gpio_channel', params, 10000); // 10 секунд
   ```

2. **Проверить размер буфера на ESP32:**
   - Убедиться, что `g_json_send_buffer[3072]` достаточно большой
   - Проверить, не возникает ли ошибка "response_too_large"

3. **Добавить retry логику:**
   - Повторять запрос при timeout
   - Максимум 3 попытки
