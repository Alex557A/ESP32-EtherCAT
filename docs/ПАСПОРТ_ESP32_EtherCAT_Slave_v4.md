## 2. Назначение и особенности

Модуль предназначен для построения распределённых систем промышленной
автоматики: обеспечивает передачу дискретных сигналов (входов и выходов)
между ведущим устройством EtherCAT (Master) и внешним оборудованием
(датчики, реле, клапаны). Применяется в системах ЧПУ (в том числе
LinuxCNC), робототехнических комплексах и стендовом оборудовании.

**Основные особенности**

1. Протокол EtherCAT (ETG.1000), 100BASE-TX, два порта (вход/выход).
2. Два контроллера Ethernet W5500 (режим MACRAW) — приём и передача
   ЭКС-фреймов без промежуточной буферизации.
3. Полноценный профиль CoE: словарь объектов, SDO (upload/download,
   сегментированный обмен, Complete Access), сервис SDO Information.
4. Конфигурируемые PDO-маппинги: RxPDO `0x1600` (выходы), TxPDO `0x1A00`
   (входы), назначение через `0x1C12` / `0x1C13`.
5. Поддержка Distributed Clock (DC): DC-Synchron (SYNC0) и Free-Run.
6. Расширяемая карта каналов ввода-вывода (до 32), конфигурация через
   Telnet (JSON-RPC) без перепрошивки.
7. Дополнительные интерфейсы: расширитель MCP23S17, квадратурные
   энкодеры, генератор STEP/DIR, шина CAN (MCP2515), радиоканал ESP-NOW.

## 5. Схемы подключения входов и выходов

### 5.1. Дискретные входы (X5)

```
+24 В ──[ датчик / контакт ]── DI_n ──[ входной делитель ]── 0 В
```

- Активный низкий уровень: при замыкании контакта на 0 В на входе
  формируется логическая «1» (объект `0x6000`).
- Допускается питание датчиков от внешнего источника 24 В.
- Неиспользуемые входы следует подключать на 0 В либо отключать в
  конфигурации (Telnet).

### 5.2. Дискретные выходы (X6)

```
DO_n (NPN, открытый коллектор) ──> нагрузка ──> +24 В
                                    │
                              обратный диод (для индуктивной нагрузки)
```

- Выход коммутирует нагрузку на 0 В; ток — не более 300 мА на канал.
- Для индуктивной нагрузки обязателен обратный диод.
- Суммарный ток группы выходов ограничен возможностями клеммной колодки.

### 5.3. Цепь питания (X3)

| Контакт | Цепь | Примечание |
|---|---|---|
| 1 | 0 В | Общий провод питания (GND) |
| 2 | PE | Заземление корпуса (шкафа) |
| 3 | +24 В | Питание модуля (отклонения ±20 %) |

## 6. Питание, заземление, требования к кабелю

1. Питание модуля — 24 В постоянного тока, нестабилизированное,
   с пульсациями не более 5 %. Рекомендуется отдельный источник
   для цепей ввода-вывода и для модуля.
2. Провод PE (контакт 2 разъёма X3) обязательно соединять с шиной
   заземления шкафа; сечение провода — не менее 1 мм².
3. Провода силовых цепей не допускается прокладывать в одном кабельном
   канале с EtherCAT-линией.
4. EtherCAT-линия — витая пара категории CAT5e или выше, с двойным
   экраном (общая фольга + оплётка). Экран заземляется с обеих сторон.
5. Максимальная длина сегмента между двумя устройствами — 100 м;
   радиус изгиба кабеля — не менее 4 диаметров.
6. Разъёмы RJ45 — экранированные, категории не ниже 5e.

## 7. Параметры EtherCAT

### 7.1. SyncManager

| SM | Назначение | Физический адрес | Длина по умолчанию | Управляющий байт | Тип (SII) |
|---|---|---|---|---|---|
| SM0 | Мailbox Out (мастер → слейв) | `0x1200` | 128 Б | `0x26` (mailbox, запись) | 1 |
| SM1 | Мailbox In (слейв → мастер) | `0x1300` | 128 Б | `0x22` (mailbox, чтение) | 2 |
| SM2 | Выходы (RxPDO) | `0x1000` | по маппингу | `0x24` (3-буфер, запись) | 3 |
| SM3 | Входы (TxPDO) | `0x1100` | по маппингу | `0x20` (3-буфер, чтение) | 4 |

Длины SM2/SM3 устанавливаются ведущим устройством в соответствии с
назначенным PDO-маппингом.

### 7.2. FMMU

| FMMU | Назначение |
|---|---|
| 0 | Выходные данные (RxPDO, запись) |
| 1 | Входные данные (TxPDO, чтение) |
| 2 | Область регистров / состояние SyncManager |

Модуль поддерживает до 8 FMMU; логический адрес преобразуется побайтно
(побитовые отображения не поддерживаются, `FMMU bit operation = 0`).

### 7.3. CoE и почтовый ящик

| Параметр | Значение |
|---|---|
| Тип почтового ящика | `0x03` (CoE) |
| Поддерживаемые сервисы | SDO Request / Response, SDO Information |
| SDO: обмен | Expedited (до 4 байт), Normal, сегментированный (до 7 байт в сегменте) |
| Complete Access | поддерживается для массивов (`0x1600`, `0x1A00`, `0x1C12`, `0x1C13`) |
| SDO Information | Get OD List, Get Object Description, Get Entry Description |
| Код ошибки при отказе | Abort SDO (стандартные коды CiA-301) |

### 7.4. Синхронизация и циклы

| Режим | Описание | Регистр активации |
|---|---|---|
| Free-Run | Обмен без синхронизации | `0x0000` |
| DC-Synchron (SYNC0) | Синхронизация по SYNC0, период задаёт мастер | `0x0300` |

| Параметр | Значение |
|---|---|
| Регистр активации DC | `0x0981` (бит 1 — SYNC0, бит 0 — циклическая работа) |
| Цикл SYNC0 | `0x09A0` (нс) |
| Время старта SYNC0 | `0x0990` (нс, 64 бита) |
| Системное время | `0x0910` (нс, 64 бита) |
| Сдвиг системного времени | `0x0920` |
| Рекомендуемые циклы | 1 / 2 / 4 / 20 мс |
| Допустимая ошибка синхронизации | не более 1 мс |

## 9. Конфигурация и монтаж

### 9.1. Настройка каналов ввода-вывода (Telnet, JSON-RPC)

Дополнительный интерфейс Telnet (порт 23) позволяет задать карту каналов
без перепрошивки:

| Команда | Назначение |
|---|---|
| `get_config` | Экспорт полной конфигурации |
| `set_config` | Импорт конфигурации (формат `get_config`) |
| `reset_config` | Сброс конфигурации к значениям по умолчанию |
| `set_gpio_channel` / `delete_gpio_channel` | Изменение отдельного канала |
| `get_gpio_channels` | Список каналов |
| `set_encoder` / `delete_encoder` / `reset_encoder` | Энкодеры |
| `set_io_expansion_config` | Расширитель MCP23S17 |
| `save_config` | Сохранение конфигурации во Flash |

Пример импорта конфигурации:

```json
{"jsonrpc":"2.0","id":1,"method":"set_config","params":{
  "save":true,
  "config":{
    "gpio_channels":[
      {"index":0,"enabled":true,"type":1,"gpio_pin":4,"pdo_byte":2,"pdo_bit":0,"name":"DI1"},
      {"index":1,"enabled":true,"type":2,"gpio_pin":5,"pdo_byte":0,"pdo_bit":0,"name":"DO1"}
    ],
    "encoders":[],
    "io_expansion":{"enabled":false}
  }}}
```

### 9.2. Монтаж

1. Модуль устанавливается на DIN-рейку 35 мм (защёлка на корпусе).
2. Соседние модули в линии EtherCAT соединяются кабелем RJ45 «вход → выход».
3. Не допускается установка вблизи мощных источников электромагнитных
   помех (частотные преобразователи, контакторы) без экранирования.
4. Обеспечить свободный доступ воздуха к корпусу; при установке в ряд
   с другими модулями соблюдать зазор не менее 10 мм сверху и снизу.

## 10. Указания по безопасности и условия эксплуатации

1. Подключение и отключение разъёмов допускается только при снятом
   питании 24 В.
2. Не превышать предельный ток каналов вывода (300 мА) — это может
   привести к выходу модуля из строя.
3. Обязательно заземлять корпус (контакт PE разъёма X3).
4. Не допускается эксплуатация при влажности с конденсацией,
   при попадании влаги и токопроводящей пыли.
5. Внесение изменений в прошивку и конфигурацию допускается только
   квалифицированным персоналом.
6. При аварийных ситуациях (перегрев, запах, дым) немедленно отключить
   питание и обратиться в службу технической поддержки.

## 11. Порядок подключения к ведущему устройству

### 11.1. TwinCAT 3 (Windows)

1. Скопировать файл `esi/ESP32_EtherCAT_Slave_v4.xml` в каталог
   `C:\TwinCAT\3.1\Config\Io\EtherCAT`.
2. Перезапустить TwinCAT в режиме Config Mode, выполнить «Reload Device
   Descriptions» в Scan Devices.
3. Выбрать устройство `ESP32 EtherCAT Slave v4` (Product Code `0x00000001`,
   Revision `0x00010000`), добавить Box.
4. Назначить переменные процесса (DO / DI), выбрать режим синхронизации
   (Free-Run или DC-Synchron), задать цикл (1 / 2 / 4 / 20 мс).

### 11.2. SOEM (Linux / Windows, язык C)

```c
ecx_config_init(&ctx);                 /* сканирование шины (чтение SII) */
ecx_config_map_group(&ctx, IOmap, 0);  /* карта процессов, PDO-маппинг */
ecx_statecheck(&ctx, 0, EC_STATE_SAFE_OP, EC_TIMEOUTSTATE);
ecx_slave[0].state = EC_STATE_OPERATIONAL;
ecx_send_processdata(&ctx);
ecx_receive_processdata(&ctx, EC_TIMEOUTRET);
/* SDO: чтение словаря */
ecx_SDOread(&ctx, 1, 0x1018, 1, FALSE, &size, &vendor_id, EC_TIMEOUTRXM);
```

### 11.3. IgH EtherCAT Master (Linux)

```bash
ethercat slaves            # список устройств (должен появиться слейв)
ethercat sdos              # выгрузка словаря объектов (SDO Information)
ethercat upload 1 0x1018 1 # чтение Vendor ID
ethercat download 1 0x1C12 1 0x1600   # назначение RxPDO
```

### 11.4. LinuxCNC

Обмен процессами выполняется через образ входов-выходов (`IOmap`):
байты 4…7 — выходы (DO), байты 8…11 — входы (DI) при стандартной карте
LinuxCNC EtherCAT (смещения соответствуют назначенным PDO).

Гарантийный срок — 12 месяцев с даты ввода в эксплуатацию при
соблюдении условий эксплуатации, изложенных в настоящем паспорте.
Гарантия не распространяется на изделия с механическими повреждениями,
следами перегрузки по току и самостоятельного ремонта.
