# Анализ новой архитектуры внешнего сервера

**Дата:** 2026-01-27  
**Версия:** 1.0  
**Статус:** Концепция

---

## Текущая архитектура (до изменений)

### Как работает сейчас:

1. **Веб-интерфейс** → отправляет запросы на `bridge.js`
2. **bridge.js** → преобразует HTTP в Telnet JSON-RPC → отправляет на ESP32
3. **ESP32** → обрабатывает команды и возвращает данные
4. **bridge.js** → преобразует ответ в HTTP → отправляет в веб-интерфейс

**Проблемы текущего подхода:**
- ❌ Сервер не знает о доступных пинах ESP32
- ❌ Невозможно создать конфигурацию без подключения к ESP32
- ❌ Нет валидации пинов на стороне сервера
- ❌ Нет поддержки разных вариантов ESP32 (ESP32-S3, ESP32, ESP32-C3)
- ❌ Конфигурация создается только после подключения к устройству

---

## Новая архитектура (концепция)

### Основная идея:

**Сервер имеет свою карту пинов и периферии для каждого варианта ESP32 и может создавать конфигурации локально, синхронизируя их с устройством по требованию.**

### Компоненты новой архитектуры:

#### 3. Configuration Builder (Построитель конфигураций)

Сервер может создавать конфигурации локально:

```javascript
class ConfigurationBuilder {
  constructor(deviceProfile) {
    this.profile = deviceProfile;
    this.config = {
      gpio_channels: [],
      encoders: [],
      stepgen: [],
      io_expansion: null,
      network: null
    };
  }
  
  // Валидация пина
  validatePin(pin, type) {
    const availablePins = this.profile.pins[type] || this.profile.pins.gpio;
    return availablePins.includes(pin);
  }
  
  // Добавление GPIO канала с валидацией
  addGPIOChannel(channel) {
    if (!this.validatePin(channel.pin, 'gpio')) {
      throw new Error(`Pin ${channel.pin} not available for ${this.profile.chip}`);
    }
    // Проверка конфликтов пинов
    // Проверка PDO mapping
    this.config.gpio_channels.push(channel);
  }
  
  // Генерация конфигурации
  build() {
    return this.config;
  }
}
```

#### 4. Sync Mechanism (Механизм синхронизации)

Синхронизация конфигурации с ESP32:

```javascript
async function syncConfigurationToDevice(ip, config) {
  const device = deviceRegistry.get(ip);
  if (!device) {
    throw new Error(`Device ${ip} not found`);
  }
  
  // 1. Определение профиля устройства (если не определен)
  if (!device.profile) {
    const systemInfo = await getSystemInfo(ip);
    device.profile = detectDeviceProfile(systemInfo);
  }
  
  // 2. Валидация конфигурации против профиля
  const profile = deviceProfiles[device.profile];
  validateConfiguration(config, profile);
  
  // 3. Отправка конфигурации на ESP32
  for (const channel of config.gpio_channels) {
    await sendJsonRpcOnce(ip, 'set_gpio_channel', channel);
  }
  
  // 4. Обновление реестра
  device.config = config;
  device.lastSynced = Date.now();
}
```

## Workflow (Процесс работы)

### Сценарий 1: Создание конфигурации для нового устройства

1. **Пользователь выбирает тип ESP32** в веб-интерфейсе:
   - ESP32-S3
   - ESP32
   - ESP32-C3

2. **Сервер загружает профиль устройства:**
   - Карта пинов
   - Доступная периферия
   - Ограничения

3. **Пользователь создает конфигурацию:**
   - Выбирает доступные пины из списка
   - Сервер валидирует выбор
   - Конфигурация сохраняется локально

4. **Подключение устройства:**
   - Пользователь вводит IP адрес
   - Сервер подключается по Telnet
   - Определяет тип устройства (если не указан)
   - Сравнивает профиль с реальным устройством

5. **Синхронизация:**
   - Пользователь нажимает "Синхронизировать"
   - Сервер отправляет конфигурацию на ESP32
   - Отображаются результаты синхронизации

### Сценарий 2: Редактирование существующей конфигурации

1. **Загрузка конфигурации:**
   - С локального хранилища (быстро)
   - С ESP32 (если нужно актуальное состояние)

2. **Редактирование:**
   - Изменение параметров
   - Валидация на лету
   - Сохранение в локальное хранилище

3. **Синхронизация:**
   - Отправка изменений на ESP32
   - Подтверждение успешной синхронизации

## Структура данных

### Device Profile

```typescript
interface DeviceProfile {
  chip: string;              // 'ESP32-S3', 'ESP32', 'ESP32-C3'
  variant: string;           // 'esp32s3', 'esp32', 'esp32c3'
  pins: {
    gpio: number[];         // Доступные GPIO пины
    spi1: { sck, miso, mosi };
    spi2: { sck, miso, mosi };
    w5500_in: { cs, rst };
    w5500_out: { cs, rst };
    usb?: { dp, dm } | null;
    can: { cs, int };
    mcp23s17: { cs };
  };
  peripherals: {
    usb: boolean;
    wifi: boolean;
    bluetooth: boolean;
    ethernet: boolean;
    can: boolean;
    io_expansion: boolean;
  };
  constraints: {
    max_gpio_channels: number;
    max_encoders: number;
    max_stepgen_axes: number;
    max_analog_inputs: number;
    max_analog_outputs: number;
  };
}
```

## Риски и ограничения

### Риски:
1. **Несоответствие профиля реальному устройству:**
   - Решение: Автоматическое определение при подключении
   - Валидация перед синхронизацией

2. **Изменение пинов в прошивке:**
   - Решение: Версионирование профилей
   - Обновление профилей при обновлении прошивки

3. **Кастомные разводки плат:**
   - Решение: Возможность создания пользовательских профилей
   - Импорт/экспорт кастомных профилей

### Ограничения:
- Профили должны обновляться при изменении прошивки
- Требуется синхронизация с реальным устройством перед использованием
