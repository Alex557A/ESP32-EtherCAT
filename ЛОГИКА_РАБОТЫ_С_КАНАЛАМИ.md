# Логика работы с USB Keyboard каналами - Двухэтапное сохранение

**Версия:** 2.0 (двухэтапное сохранение: локальное хранилище + синхронизация с ESP32)  
**Дата обновления:** 2026-01-27

## Архитектура двухэтапного сохранения

### Этап 1: Локальное хранилище на сервере bridge.js

Каналы сохраняются в памяти Node.js сервера (`Map localChannels`) перед отправкой на ESP32.

### Этап 2: Синхронизация с ESP32

Явная синхронизация всех локальных каналов с ESP32 по кнопке "💾 Сохранить на ESP32".

---

## Полный цикл работы с каналами

### 1. Создание нового канала

**Шаги:**
1. Пользователь выбирает категорию "USB Keyboard"
2. Нажимает клавишу на физической клавиатуре → автоматически заполняются:
   - USB key code (HEX)
   - USB кнопка (выпадающий список)
   - Модификаторы (чекбоксы)
   - Index (следующий свободный из локального хранилища)
   - PDO byte (следующий свободный из локального хранилища)
3. Заполняет вручную поле **Name**
4. Нажимает кнопку **"Apply"**

**Что происходит при нажатии "Apply":**
```javascript
saveIOChannel() {
  1. Собирает данные из формы
  2. Запрашивает локальные каналы: GET /api/devices/{ip}/gpio/channels/local
  3. Если Index не указан → автоматически находит следующий свободный индекс
  4. Если PDO byte не указан → автоматически находит следующий свободный PDO byte
  5. Отправляет POST запрос: /api/devices/{ip}/gpio/channel
     {
       index: <число или отсутствует>,
       enabled: true/false,
       category: "USB_KEY",
       name: "...",
       usb_key_code: 0x04,
       usb_modifiers: 0x00,
       pdo_byte: 0,
       pdo_bit: 0,
       ...
     }
  6. Backend (bridge.js) обрабатывает запрос:
     - Сохраняет канал в Map localChannels[ip]
     - Если index указан → обновление существующего канала
     - Если index не указан → создание нового канала (index = channels.length)
  7. После успешного сохранения:
     - Вызывает loadDeviceGPIOChannels() → загружает из локального хранилища
     - Обновляет визуальную таблицу каналов
     - Очищает форму (ioChSelect = "", loadChannelToForm({}))
     - Показывает alert "Канал успешно сохранен в локальное хранилище!"
}
```

**Важно:** Канал сохраняется только в локальное хранилище на сервере, НЕ на ESP32!

### 2. Отображение списка созданных каналов

**После сохранения канала:**

1. **Визуальная таблица каналов** (`channelsTable`):
   - Отображает все каналы из локального хранилища
   - Колонки: Index | Name | Category | USB Key | Modifiers | PDO Byte | Actions
   - Кнопки "Edit" и "Delete" в каждой строке
   - Обновляется автоматически через `loadDeviceGPIOChannels()`

2. **Выпадающий список каналов** (`ioChSelect`):
   - Обновляется автоматически через `loadDeviceGPIOChannels()`
   - Загружает данные из локального хранилища: `GET /api/devices/{ip}/gpio/channels/local`
   - Формат опций: `[0] Name (USB_KEY)`
   - Пример: `[0] Button_A (USB_KEY)`, `[1] Enter_Key (USB_KEY)`
   - Позволяет выбрать канал для редактирования

3. **JSON отображение** (`ioChannelsRaw`):
   - Отображает полный JSON массив всех каналов из локального хранилища
   - Показывает все параметры каждого канала
   - Формат: `<pre class="code">[{...}, {...}]</pre>`

**Текущее состояние:**
- ✅ Визуальная таблица каналов отображает локальные каналы
- ✅ Список каналов доступен в выпадающем списке
- ✅ Полные данные доступны в JSON формате
- ✅ Все данные берутся из локального хранилища на сервере

### 3. Редактирование существующего канала

**Шаги:**
1. Пользователь выбирает канал из выпадающего списка `ioChSelect` или нажимает "Edit" в таблице
2. Обработчик `change` события или `editChannel(index)`:
   ```javascript
   // Из выпадающего списка
   ioChSelect.addEventListener('change', async (e) => {
     const index = e.target.value;
     if (!index) {
       loadChannelToForm({}, undefined); // Очистка формы
       return;
     }
     // Загружаем данные канала из локального хранилища
     const resp = await fetch(`/api/devices/${ip}/gpio/channels/local`);
     const data = await resp.json();
     loadChannelToForm(data[index], index); // Заполняем форму
   });
   
   // Из таблицы (кнопка "Edit")
   function editChannel(index) {
     ioChSelect.value = index;
     ioChSelect.dispatchEvent(new Event('change'));
     // Прокрутка к форме
   }
   ```
3. Форма заполняется данными канала через `loadChannelToForm()`:
   - Index → устанавливается значение индекса
   - Name → имя канала
   - USB key code → код клавиши
   - Модификаторы → чекбоксы отмечаются
   - PDO byte/bit → значения PDO
   - Все остальные поля
4. Пользователь изменяет нужные поля
5. Нажимает **"Apply"** → канал обновляется в локальном хранилище (так как Index уже указан)

**Важно:**
- Кнопка "Apply" используется как для создания, так и для обновления
- Все изменения сохраняются только в локальное хранилище на сервере
- Backend определяет операцию по наличию параметра `index`:
  - `index` указан → обновление существующего канала в `localChannels`
  - `index` не указан → создание нового канала в `localChannels`

### 4. Удаление канала

**Шаги:**
1. Пользователь выбирает канал из выпадающего списка, таблицы или вводит Index вручную
2. Нажимает кнопку **"Delete by index"** или кнопку "Delete" в таблице
3. Функция `deleteChannelFromTable(index)` или `deleteIOChannel()`:
   ```javascript
   // Из таблицы
   async function deleteChannelFromTable(index) {
     1. Показывает confirm "Удалить канал [X]?"
     2. Отправляет POST запрос: /api/devices/{ip}/gpio/channel/delete/local
        { index: X }
     3. Backend удаляет канал из Map localChannels[ip]
     4. После успешного удаления:
        - Вызывает loadDeviceGPIOChannels() → обновляет список из локального хранилища
        - Очищает форму
        - Показывает alert "Канал успешно удален из локального хранилища!"
   }
   
   // Из формы
   deleteIOChannel() {
     1. Проверяет, что Index указан
     2. Показывает confirm "Удалить канал [X]?"
     3. Отправляет POST запрос: /api/devices/{ip}/gpio/channel/delete/local
        { index: X }
     4. Backend удаляет канал из Map localChannels[ip]
     5. После успешного удаления:
        - Вызывает loadDeviceGPIOChannels() → обновляет список
        - Очищает форму
        - Показывает alert "Канал успешно удален из локального хранилища!"
   }
   ```

**Важно:** Удаление происходит только из локального хранилища, НЕ с ESP32!

### 5. Обновление списка каналов

**Функция `loadDeviceGPIOChannels()`:**
```javascript
async function loadDeviceGPIOChannels() {
  1. Отправляет GET запрос: /api/devices/{ip}/gpio/channels/local
  2. Получает массив каналов из локального хранилища на сервере
  3. Отображает JSON в <pre id="ioChannelsRaw">
  4. Заполняет визуальную таблицу channelsTable через renderChannelsTable(data)
  5. Заполняет выпадающий список ioChSelect:
     - Опция "-- Новый канал --" (value="")
     - Для каждого канала: [index] name (category)
  6. Вызывает autoFillChannelFields() для автоматического заполнения
}
```

**Когда вызывается:**
- После создания канала (`saveIOChannel()`)
- После удаления канала (`deleteChannelFromTable()` или `deleteIOChannel()`)
- При ручной загрузке (кнопка "Загрузить локальные каналы")
- При изменении активного устройства

**Важно:** По умолчанию загружаются каналы из локального хранилища, НЕ с ESP32!

### 6. Синхронизация каналов с ESP32

**Шаги:**
1. Пользователь подготавливает все каналы в локальном хранилище (создание, редактирование)
2. Нажимает кнопку **"💾 Сохранить на ESP32"**
3. Функция `syncChannelsToESP32()`:
   ```javascript
   async function syncChannelsToESP32() {
     1. Отправляет POST запрос: /api/devices/{ip}/gpio/channels/sync
     2. Backend (bridge.js) обрабатывает запрос:
        - Получает все каналы из Map localChannels[ip]
        - Для каждого канала отправляет JSON-RPC команду set_gpio_channel на ESP32
        - Отслеживает успешные и неудачные синхронизации
     3. Возвращает результат:
        {
          success: true,
          synced: 5,      // Количество успешно синхронизированных
          errors: 0,      // Количество ошибок
          results: [...]  // Детальные результаты по каждому каналу
        }
     4. После синхронизации:
        - Показывает alert с результатами синхронизации
        - Опционально: вызывает loadDeviceGPIOChannelsFromESP32() для проверки
   }
   ```

**Важно:** 
- Синхронизация отправляет ВСЕ каналы из локального хранилища на ESP32
- Каждый канал отправляется отдельной JSON-RPC командой `set_gpio_channel`
- После синхронизации каналы доступны для использования в EtherCAT PDO

### 7. Загрузка каналов с ESP32

**Функция `loadDeviceGPIOChannelsFromESP32()`:**
```javascript
async function loadDeviceGPIOChannelsFromESP32() {
  1. Отправляет GET запрос: /api/devices/{ip}/gpio/channels
  2. Получает массив каналов напрямую с ESP32 (через Telnet)
  3. Обновляет локальное хранилище: localChannels[ip] = data
  4. Отображает каналы в таблице и выпадающем списке
  5. Показывает alert "Каналы загружены с ESP32"
}
```

**Когда используется:**
- При необходимости синхронизировать локальное хранилище с данными на ESP32
- После изменения каналов напрямую на ESP32 (через другой интерфейс)
- Для проверки после синхронизации
