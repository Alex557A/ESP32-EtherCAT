# Настройка сети для параллельной работы EtherCAT и Telnet

## Проблема

Сервер работает, но не может подключиться к ESP32 по Telnet, потому что:
- ESP32 находится в сети `192.168.20.0/24` (IP: `192.168.20.1`)
- Компьютер находится в другой сети (например, `192.168.1.0/24`)
- Нет маршрута к сети ESP32

## Решение

Нужно настроить сетевой интерфейс, который используется для EtherCAT, чтобы он также работал с TCP/IP для Telnet.

## Архитектура

```
Физический интерфейс (enp3s0)
    │
    ├─ Socket 0: EtherCAT (MACRAW mode)
    │   └─ Обработка EtherCAT фреймов
    │
    └─ Socket 1: Telnet (TCP/IP mode)
        └─ TCP соединение на порт 23
```

**Важно:** Оба протокола работают **параллельно** на одном физическом интерфейсе!

## Быстрая настройка

### Шаг 1: Проверка текущей конфигурации

```bash
cd /media/alex/One/EtherCAT/ESP32_EtherCAT_Slave_4/tools/http-telnet-bridge
./check_network.sh
```

### Шаг 2: Настройка сети (временная)

```bash
sudo ./setup_network.sh
```

Это настроит:
- IP адрес `192.168.20.100` на интерфейсе `enp3s0`
- Маршрут к сети `192.168.20.0/24`
- Проверит доступность ESP32

### Шаг 3: Проверка соединения

```bash
# Проверка ping
ping -c 2 192.168.20.1

# Проверка Telnet (если установлен netcat)
nc -zv 192.168.20.1 23
```

### Шаг 4: Запуск сервера

```bash
./start_server.sh
# или для разработки
./start_dev.sh
```

## Постоянная настройка

Для сохранения конфигурации после перезагрузки:

```bash
sudo ./setup_network_permanent.sh
```

Это создаст конфигурацию в:
- **Ubuntu 18.04+**: `/etc/netplan/01-ethercat-telnet.yaml`
- **Debian/старые версии**: `/etc/network/interfaces.d/enp3s0`

## Ручная настройка

### Вариант 1: Через ip команды

```bash
# Настройка IP адреса
sudo ip addr add 192.168.20.100/24 dev enp3s0
sudo ip link set enp3s0 up

# Проверка
ip addr show enp3s0
ping -c 2 192.168.20.1
```

### Вариант 2: Через netplan (Ubuntu 18.04+)

Создайте файл `/etc/netplan/01-ethercat-telnet.yaml`:

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp3s0:
      addresses:
        - 192.168.20.100/24
      dhcp4: false
```

Примените:
```bash
sudo netplan apply
```

### Вариант 3: Через /etc/network/interfaces

Создайте файл `/etc/network/interfaces.d/enp3s0`:

```
auto enp3s0
iface enp3s0 inet static
    address 192.168.20.100
    netmask 255.255.255.0
```

Примените:
```bash
sudo ifdown enp3s0 && sudo ifup enp3s0
# или
sudo systemctl restart networking
```

## Определение интерфейса для EtherCAT

Если интерфейс не `enp3s0`, определите его:

```bash
# Список всех интерфейсов
ip link show

# Проверка, какой интерфейс подключен к EtherCAT Master
# (обычно это интерфейс, который не имеет IP адреса и используется для EtherCAT)
```

Затем укажите интерфейс при запуске скрипта:

```bash
ETHERCAT_INTERFACE=eth0 sudo ./setup_network.sh
```

## Проверка работы

После настройки проверьте:

```bash
# 1. Проверка IP адреса
ip addr show enp3s0 | grep "inet "

# 2. Проверка маршрутов
ip route | grep 192.168.20

# 3. Проверка доступности ESP32
ping -c 2 192.168.20.1

# 4. Проверка Telnet порта
nc -zv 192.168.20.1 23

# 5. Проверка работы сервера
curl http://localhost:3000
```

## Устранение проблем

### Проблема: "ESP32 недоступен по ping"

**Возможные причины:**
1. ESP32 не подключен к сети
2. Неправильный IP адрес ESP32
3. Проблемы с кабелем/коммутатором

**Решение:**
- Проверьте физическое подключение
- Проверьте IP адрес ESP32 (должен быть `192.168.20.1` или другой в сети `192.168.20.0/24`)
- Проверьте настройки сети на ESP32

### Проблема: "Telnet порт недоступен"

**Возможные причины:**
1. Telnet сервер не запущен на ESP32
2. Firewall блокирует соединение
3. Неправильный порт

**Решение:**
- Проверьте, что Telnet сервер запущен на ESP32
- Проверьте настройки firewall: `sudo ufw status`
- Проверьте порт: `nc -zv 192.168.20.1 23`

### Проблема: "Интерфейс не найден"

**Возможные причины:**
1. Интерфейс имеет другое имя
2. Интерфейс не подключен

**Решение:**
- Найдите правильное имя: `ip link show`
- Укажите правильный интерфейс: `ETHERCAT_INTERFACE=eth0 sudo ./setup_network.sh`

### Проблема: "Конфликт с EtherCAT Master"

**Важно:** Настройка IP адреса на интерфейсе **НЕ мешает** работе EtherCAT!

EtherCAT работает на уровне MACRAW (Socket 0), а TCP/IP на уровне TCP (Socket 1). Они работают параллельно.

Если все же есть проблемы:
- Убедитесь, что EtherCAT Master использует правильный интерфейс
- Проверьте настройки EtherCAT Master

## Дополнительная информация

- **EtherCAT**: Использует Socket 0 в режиме MACRAW
- **Telnet**: Использует Socket 1 в режиме TCP
- **Физический интерфейс**: Один и тот же для обоих протоколов
- **IP адрес**: Нужен только для TCP/IP (Telnet), не влияет на EtherCAT
