# Быстрая диагностика ошибки Telnet подключения

## Ошибка: `ECONNREFUSED 192.168.20.1:23`

Это означает, что соединение было отклонено. ESP32 либо не запущен, либо Telnet сервер не работает.

## Быстрая проверка (5 минут)

### 1. Проверьте Serial Monitor ESP32

**Откройте Serial Monitor (115200 baud) и найдите:**

```
[Network] IP: 192.168.20.X
[Telnet] ✓ Server started, waiting for connections...
```

**Важно:** Запишите реальный IP адрес (может быть не 192.168.20.1!)

### 2. Проверьте IP адрес в веб-интерфейсе

1. Откройте http://localhost:3000
2. В разделе "Devices" проверьте активное устройство
3. Если IP адрес не совпадает с Serial Monitor → измените его

### 3. Проверьте сеть на ПК

**Windows:**
```powershell
# Проверьте IP адрес
ipconfig

# Должен быть в подсети 192.168.20.X
# Если нет - настройте:
netsh interface ip set address "Ethernet" static 192.168.20.100 255.255.255.0 192.168.20.1
```

**Linux/macOS:**
```bash
# Проверьте IP адрес
ip addr show  # или ifconfig

# Должен быть в подсети 192.168.20.X
```

### 4. Проверьте физическое подключение

- ✅ Кабель Ethernet подключен к W5500_IN
- ✅ ESP32 включен и прошит
- ✅ Нет ошибок в Serial Monitor

## Решения

### Решение 1: Обновить IP адрес в веб-интерфейсе

1. Откройте http://localhost:3000
2. Найдите раздел "Devices"
3. Если видите другой IP адрес → выберите его как активное устройство
4. Или добавьте новый IP адрес из Serial Monitor

### Решение 2: Обновить IP через переменные окружения

**Остановите bridge.js (Ctrl+C) и запустите:**

**Windows:**
```cmd
set TELNET_HOST=192.168.20.X
node bridge.js
```

**Linux/macOS:**
```bash
export TELNET_HOST=192.168.20.X
node bridge.js
```

(Замените X на реальный IP адрес из Serial Monitor)

### Решение 3: Проверить, что ESP32 запущен

**В Serial Monitor должны быть видны:**
```
[MAIN] Initializing...
[Network] IP: 192.168.20.X
[Telnet] ✓ Server started
```

**Если нет:**
- Перезагрузите ESP32 (кнопка RESET)
- Проверьте, что прошивка загружена
- Проверьте питание ESP32

### Решение 4: Проверить сетевые настройки

**ESP32 должен быть в подсети 192.168.20.0/24**

**ПК должен быть в той же подсети:**
- IP: 192.168.20.100 (или любой другой, кроме адреса ESP32)
- Subnet: 255.255.255.0
- Gateway: 192.168.20.1 (или не нужен)

## Тест подключения

**Попробуйте подключиться напрямую через telnet:**

**Windows:**
```cmd
telnet 192.168.20.X 23
```

**Linux/macOS:**
```bash
telnet 192.168.20.X 23
```

**Если подключение успешно:**
- Telnet сервер работает
- Проблема в IP адресе в bridge.js

**Если не подключается:**
- Проверьте Serial Monitor
- Проверьте сетевые настройки
- Проверьте физическое подключение

## Чек-лист

- [ ] Serial Monitor открыт и показывает IP адрес
- [ ] IP адрес записан из Serial Monitor
- [ ] IP адрес в веб-интерфейсе совпадает с Serial Monitor
- [ ] ПК в той же подсети (192.168.20.X)
- [ ] Кабель Ethernet подключен
- [ ] ESP32 включен и прошит
- [ ] Telnet сервер запустился (видно в Serial Monitor)

## Если ничего не помогает

1. **Перезагрузите ESP32** (кнопка RESET)
2. **Перезапустите bridge.js** (Ctrl+C и снова `node bridge.js`)
3. **Проверьте, что порт 23 не занят** на ESP32
4. **Проверьте firewall** на ПК (может блокировать подключения)
