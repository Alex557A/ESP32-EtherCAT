# Исправление проблемы переподключения Telnet

## Проблема

Соединение с ESP32 устанавливается успешно, но затем разрывается:
- `ECONNRESET` - соединение разорвано удаленной стороной
- `ETIMEDOUT` - таймаут при переподключении

## Причины

1. **Нет keepalive** - соединение закрывается из-за неактивности
2. **Нет обработки таймаутов** - при разрыве соединения не происходит корректного переподключения
3. **Бесконечные попытки переподключения** - нет ограничения на количество попыток
4. **Нет экспоненциальной задержки** - постоянные попытки переподключения могут перегружать сеть

## Реализованные исправления

### 1. Keepalive для поддержания соединения

```javascript
telnetClient.setKeepAlive(true, 60000); // Keepalive каждые 60 секунд
telnetClient.setNoDelay(true); // Отключить Nagle algorithm для низкой задержки
```

**Эффект:**
- Соединение остается активным даже при отсутствии данных
- Снижается вероятность разрыва соединения из-за неактивности

### 2. Таймаут подключения

```javascript
telnetClient.setTimeout(10000, () => {
    console.error(`[Telnet] Connection timeout to ${host}:${TELNET_PORT}`);
    telnetClient.destroy();
});
```

**Эффект:**
- Предотвращает бесконечное ожидание подключения
- Автоматически закрывает соединение при таймауте

### 3. Ограничение попыток переподключения

```javascript
const MAX_RECONNECT_ATTEMPTS = 10;
let reconnectAttempts = 0;

if (reconnectAttempts >= MAX_RECONNECT_ATTEMPTS) {
    console.error(`[Telnet] Max reconnect attempts reached. Stopping reconnection.`);
    return;
}
```

**Эффект:**
- Предотвращает бесконечные попытки переподключения
- Останавливает попытки после 10 неудачных попыток
- Сбрасывает счетчик при успешном подключении

### 4. Экспоненциальная задержка переподключения

```javascript
const delay = Math.min(RECONNECT_DELAY * Math.pow(1.5, reconnectAttempts - 1), 30000);
// Максимум 30 секунд между попытками
```

**Эффект:**
- Первая попытка: 5 секунд
- Вторая попытка: 7.5 секунд
- Третья попытка: 11.25 секунд
- И так далее до максимума 30 секунд

**Преимущества:**
- Снижает нагрузку на сеть при множественных попытках
- Дает больше времени ESP32 на восстановление

### 5. Улучшенная обработка ошибок

```javascript
telnetClient.on('error', (err) => {
    if (errorMsg.includes('ECONNRESET') || errorMsg.includes('ETIMEDOUT')) {
        // Эти ошибки обрабатываются через событие 'close'
    } else {
        // Другие ошибки - переподключаемся сразу
        telnetClient.destroy();
    }
});
```

**Эффект:**
- Корректная обработка различных типов ошибок
- Предотвращение двойного переподключения

### 6. Обработка события timeout

```javascript
telnetClient.on('timeout', () => {
    console.error(`[Telnet] Socket timeout`);
    telnetClient.destroy();
});
```

**Эффект:**
- Корректная обработка таймаутов сокета
- Автоматическое закрытие соединения при таймауте

## Использование

### Автоматическое переподключение

При разрыве соединения:
1. Соединение закрывается
2. Запускается таймер переподключения с экспоненциальной задержкой
3. После задержки выполняется попытка переподключения
4. При успешном подключении счетчик попыток сбрасывается
5. После 10 неудачных попыток переподключение останавливается

### Ручное переподключение

Если переподключение остановлено (достигнут максимум попыток):
1. Перезапустите bridge.js
2. Или измените активное устройство в веб-интерфейсе

## Мониторинг

В консоли bridge.js отображается:
- `[Telnet] Reconnect attempt X/10...` - попытка переподключения
- `[Telnet] Reconnecting in X seconds...` - задержка до следующей попытки
- `[Telnet] Max reconnect attempts reached` - достигнут максимум попыток

## Рекомендации

1. **Если соединение постоянно разрывается:**
   - Проверьте стабильность сети
   - Проверьте, что ESP32 не перезагружается
   - Проверьте настройки Telnet сервера на ESP32

2. **Если переподключение не происходит:**
   - Проверьте логи bridge.js
   - Убедитесь, что ESP32 доступен по сети
   - Проверьте firewall на ПК

3. **Если достигнут максимум попыток:**
   - Проверьте, что ESP32 запущен и доступен
   - Перезапустите bridge.js
   - Проверьте сетевые настройки

## Тестирование

После применения исправлений:

1. **Запустите bridge.js:**
   ```bash
   node bridge.js
   ```

2. **Проверьте подключение:**
   - Должно появиться: `[Telnet] Connected to 192.168.20.1:23`
   - Соединение должно оставаться активным

3. **Проверьте переподключение:**
   - Отключите ESP32 от сети
   - Должны появиться сообщения о переподключении
   - Подключите ESP32 обратно
   - Соединение должно восстановиться автоматически
