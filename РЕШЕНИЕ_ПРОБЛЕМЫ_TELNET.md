# Решение проблемы подключения Telnet

## Статус ESP32

✅ **ESP32 работает правильно!**

Из Serial Monitor видно:
- ✅ Network Configuration инициализирована: IP = 192.168.20.1
- ✅ W5500 TCP инициализирован для Telnet
- ✅ Telnet Server инициализирован
- ✅ Telnet Server запущен: "✓ Server started, waiting for connections..."
- ✅ IP адрес правильный: 192.168.20.1:23

## Проблема

Bridge.js не может подключиться к ESP32, хотя ESP32 показывает что сервер запущен.

## Возможные причины

### 1. Сетевые настройки на ПК

**Проверьте IP адрес ПК:**

Windows:
```powershell
ipconfig
```

**Должен быть в подсети 192.168.20.X (где X ≠ 1)**

Если нет - настройте:
```powershell
netsh interface ip set address "Ethernet" static 192.168.20.100 255.255.255.0 192.168.20.1
```

### 2. Firewall блокирует подключение

**Windows Firewall может блокировать входящие подключения.**

**Решение:**
1. Откройте "Брандмауэр Защитника Windows"
2. Нажмите "Дополнительные параметры"
3. Создайте правило для входящих подключений на порт 23
4. Или временно отключите firewall для теста

### 3. Проблема с bridge.js

**Проверьте, что bridge.js использует правильный IP адрес:**

В консоли bridge.js должно быть:
```
[Telnet] Connecting to 192.168.20.1:23...
```

Если другой IP - обновите:
```bash
set TELNET_HOST=192.168.20.1
node bridge.js
```

## Тестирование

### Тест 1: Прямое подключение через telnet

**Попробуйте подключиться напрямую:**

Windows:
```cmd
telnet 192.168.20.1 23
```

**Если подключение успешно:**
- ✅ Telnet сервер работает
- ✅ Проблема в bridge.js или сетевых настройках ПК

**Если не подключается:**
- Проверьте сетевые настройки ПК
- Проверьте firewall
- Проверьте физическое подключение кабеля

### Тест 2: Ping ESP32

**Проверьте доступность ESP32:**

```cmd
ping 192.168.20.1
```

**Должен быть ответ:**
```
Reply from 192.168.20.1: bytes=32 time<1ms TTL=64
```

**Если нет ответа:**
- Проверьте сетевые настройки ПК
- Проверьте физическое подключение кабеля
- Проверьте, что ESP32 действительно на IP 192.168.20.1

### Тест 3: Проверка порта

**Проверьте, что порт 23 открыт:**

Windows:
```powershell
Test-NetConnection -ComputerName 192.168.20.1 -Port 23
```

**Должно быть:**
```
TcpTestSucceeded : True
```

**Если False:**
- Порт закрыт или недоступен
- Проверьте firewall
- Проверьте, что Telnet сервер действительно запущен

## Решения

### Решение 1: Настроить сеть на ПК

1. **Проверьте текущий IP:**
   ```powershell
   ipconfig
   ```

2. **Если не в подсети 192.168.20.X:**
   ```powershell
   netsh interface ip set address "Ethernet" static 192.168.20.100 255.255.255.0 192.168.20.1
   ```

3. **Проверьте подключение:**
   ```cmd
   ping 192.168.20.1
   ```

### Решение 2: Отключить Firewall (временно для теста)

1. Откройте "Брандмауэр Защитника Windows"
2. Нажмите "Включение и отключение брандмауэра Защитника Windows"
3. Временно отключите firewall для частной сети
4. Попробуйте подключиться снова

**Важно:** Включите firewall обратно после теста!

### Решение 3: Проверить bridge.js

1. **Остановите bridge.js** (Ctrl+C)

2. **Запустите с явным указанием IP:**
   ```bash
   set TELNET_HOST=192.168.20.1
   node bridge.js
   ```

3. **Проверьте логи:**
   - Должно быть: `[Telnet] Connecting to 192.168.20.1:23...`
   - Если другой IP - обновите переменную окружения

### Решение 4: Проверить физическое подключение

1. **Проверьте кабель Ethernet:**
   - Кабель подключен к W5500_IN на ESP32
   - Кабель подключен к ПК (или коммутатору)
   - Нет повреждений кабеля

2. **Проверьте индикаторы:**
   - Индикаторы на сетевой карте ПК горят
   - Индикаторы на W5500 (если есть) горят
